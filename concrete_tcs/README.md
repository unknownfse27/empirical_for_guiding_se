# Concrete Test Cases
We provide test cases generated by 10 third-year undergraduate students majoring in computer science to test nine programs: bison-3.8, diff-3.7, find-4.7.0, gawk-5.1.0, gcal-4.1, grep-3.6, m4-1.4.19, sed-4.8, and sqlite-3.33.0.

## Structure
The directory structure is organized as follows:
```
.
├── configs
│   └── <program>
│       ├── <student_idx>
│       │   ├── <test_case_idx>.json
│       │   └── ...
│       └── inputs
└── seeds
    └── <program>
```

Each \<program> directory corresponds to one of the nine benchmark programs.

In configs/\<program>, each <student_idx> directory corresponds to one of the 10 students who created test cases for that program. Each <test_case_idx>.json file represents a single test case created by the corresponding student.

The inputs directory contains the input files referenced by the test cases for the corresponding program.

The seeds/\<program> directory contains seed files generated from the concrete test cases using KLEE's gen-bout command. The gen-bout command converts concrete test cases into a format that can be consumed as seed inputs by KLEE-based symbolic execution techniques.


## Details
Each test case in configs/\<program>/<student_idx> is represented as a JSON file with the following structure:
```
{
  "envs": [],
  "args": [
    <arguments>
  ],
  "dirs": [],
  "files": [
    <input_files>
  ],
  "stdin": "..."
}
```
Each field specifies a component of the concrete test case:
* envs: environment variables used during execution.
* args: command-line arguments passed to the target program.
* dirs: directories required by the test case.
* files: input files used by the test case.
* stdin: data provided through standard input.

The special token @@ in args indicates the position at which the corresponding input file is supplied when executing the target program.

## How to Replay
The student-generated test cases can be replayed using `replay.py`. The script executes the concrete test cases for the selected program and measures the branch coverage achieved by replaying them.

For example, to replay the test cases for bison, run:
```
/concrete_tcs$ LC_ALL=C.UTF-8 LANG=C.UTF-8 python3 replay.py --programs bison
```

Then, this script replays each student-generated test case on the corresponding GCOV-instrumented program and reports the accumulated branch coverage as:
```
[INFO] Replaying student-written test cases for bison program
[INFO] Replaying test cases: 50/283 -> Accumulated coverage : 9178
[INFO] Replaying test cases: 100/283 -> Accumulated coverage : 9643
[INFO] Replaying test cases: 150/283 -> Accumulated coverage : 9810
[INFO] Replaying test cases: 200/283 -> Accumulated coverage : 9844
[INFO] Replaying test cases: 250/283 -> Accumulated coverage : 9931
[INFO] Replay done. the accumulated coverage for bison program : 9945
```


The --programs option specifies the target program to replay. Multiple programs can be provided at once:

```
/concrete_tcs$ LC_ALL=C.UTF-8 LANG=C.UTF-8 python3 replay.py --programs bison grep m4
```

To replay the test cases for all benchmark programs, run:

```
/concrete_tcs$ LC_ALL=C.UTF-8 LANG=C.UTF-8 python3 replay.py --programs all
```
